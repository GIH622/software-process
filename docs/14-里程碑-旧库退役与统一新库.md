## 1. 为什么要做这个里程碑

前期为兼容队友导出的真实库 `library_db.sql`，代码里留下了多处"名不副实"的兼容逻辑。项目实际使用独立开发库 `library_dev`，旧库只是过渡参考物，这些兼容逻辑只剩成本、没有收益：

| # | 兼容逻辑 | 问题 |
|---|---|---|
| P1 | 口令列叫 `password_md5`，实际存 BCrypt | 名不副实，varchar(64) 装哈希全靠注释约定 |
| P2 | MD5 登录兼容 + 升级开关（默认关） | 弱哈希可无限期登录；开关永不开启，纯死代码 |
| P3 | FROZEN 粘滞 + 解冻时构造假 Reader 绕行 | 同一系统两套语义，靠注释解释，易踩坑 |
| P4 | 测试 tc029 专测 MD5 兼容 | 验证一个本应消失的行为 |
| P5 | `sql/library_db.sql` 被 Git 跟踪 | 每次提交都分发含 `DROP TABLE` 的旧库快照 |
| P6 | `library_init.sql` 自称"兼容旧库字段" | 新库仍在复制旧结构 |
